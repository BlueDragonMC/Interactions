## Usage

Create a `PlacementRuleRegistry`, register rules into it, then attach its event node to the global event
handler (or to a specific instance's event node to scope the rules to that instance).

```kotlin
// Every bundled rule:
val registry = PlacementRuleRegistry()
RuleCatalog.registerAll(registry)
MinecraftServer.getGlobalEventHandler().addChild(registry.eventNode())
```

```kotlin
// Or a curated subset:
val registry = PlacementRuleRegistry()
registry.register(ButtonPlacementRule())
instance.eventNode().addChild(registry.eventNode())
```

### Block entity NBT

Placement rules only control block state, not block entity data. To let clients see NBT for block
entities in existing worlds (sign text, container contents, beacon effects, ...), register the bundled
tag-only handlers with Minestom's block manager:

```kotlin
for (handler in BlockHandlers.getAll()) {
    MinecraftServer.getBlockManager().registerHandler(handler.key) { handler }
}
```

Each handler only provides `getBlockEntityTags()`. This is independent of placement rules, and because
it uses Minestom's block manager it is global rather than per-instance.

## Demo Server

This project includes a Minestom server that you can use to test out the block behaviors. To use it, run:
```sh
./gradlew :demo:run
```

## Coverage

Implementation progress for every stateful block is tracked in [COVERAGE.md](COVERAGE.md), which is
generated by the `:tools:coverage` module:

```sh
./gradlew :tools:coverage:run
```

CI runs `:tools:coverage:verifyCoverage` and fails if the generated documentation is stale.

## Why another placement library?

In their current form, block handlers are a finicky system. They require cooperation from an instance's chunk loader, and they need to be manually applied when a player places a block. This library uses events instead, which makes block behavior easier to reason about, with the additional benefit of allowing behaviors to be scoped using Minestom's powerful event system.
